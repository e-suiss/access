# L0 Meta-actions

Status: first draft, core track version 1. Not yet adopted.

A meta-action is an Exercise that changes authority state. Apart from Genesis, it is the only way authority state changes. This part defines the meta-action payloads, the identifiers they create, the state they write and the authority each one needs. The data model is in [`kernel.cddl`](../../conformance/cddl/kernel.cddl): `meta-payload`, `genesis-fields`, the `*-state` rules and `exercise-basis`.

## 1. Payload and identifiers

<a id="L0-META-1"></a>**L0-META-1. Core actions.** A meta-action is an intent whose action has namespace `access` and one of the names of `meta-payload`: `anchor_create`, `anchor_transfer`, `anchor_amend`, `anchor_retire`, `party_register`, `party_depart`, `instance_create`, `instance_rekey`, `instance_terminate`, `instance_recover`, `mandate_bind`, `mandate_rebind`, `mandate_revoke`, `grant_issue`, `grant_amend`, `grant_revoke`, `grant_renounce`, `acceptance_establish`, `acceptance_amend`, `acceptance_revoke`, `policy_set`, `policy_retire`, `claim_issue`, `contribute`, `consumption_release`, `authority_set_define`, `projection_issue`. Its body is a `meta-payload` whose single key is the action name. A body whose key differs from the action name, or that does not decode as `meta-payload`, is malformed (reason `meta-malformed`). An implementation that builds a payload in memory decides it only if the payload's encoding decodes back to the same payload, so that every identifier it names is one the codec accepts and no state is written that cannot be read back; any other payload is malformed.

<a id="L0-META-2"></a>**L0-META-2. Payload digest.** The body enters the intent as `intent.opaque.payload = SHA-256("access/meta/v1" ‖ 0x00 ‖ dCBOR(meta-payload))`. A receiver recomputes the digest from the body it is given and never takes it from the input.

<a id="L0-META-3"></a>**L0-META-3. ExerciseID.** `ExerciseID = SHA-256("access/exercise/v1" ‖ 0x00 ‖ dCBOR([DomainID, nonce]))`, where `DomainID` is encoded as a `digest` and `nonce` as a byte string.

<a id="L0-META-4"></a>**L0-META-4. Object identifiers.** The `n`-th object of kind `k` that an Exercise creates has the id `SHA-256("access/object/v1" ‖ 0x00 ‖ dCBOR([origin, k, n]))` truncated to its first 16 bytes. `origin` is the ExerciseID, or the DomainID for objects created by Genesis; both are encoded as a `digest`. `n` counts from 0 within each kind.

## 2. State

<a id="L0-META-5"></a>**L0-META-5. State keys.** The state key of an object is `dCBOR([k, id])`, where `k` is the kind text and `id` its identifier. The kinds are `anchor`, `grant`, `party`, `instance`, `mandate`, `acceptance`, `policy`, `claim` and `contribution`. A Claim is keyed by its ClaimID. A contribution, and an allowed Exercise (`exercise`: its intent digest, actor Instance and position, written by the allowing decision), and a projection (`projection`, [L0-META-35](#L0-META-35)), are keyed `dCBOR([k, ExerciseID])` with the ExerciseID encoded as a `digest`. Seven index kinds hold sets of ids: `children` (the Grants whose basis is an Anchor or a Grant, keyed by that id), `instances` (the Instances of a Party, keyed by the Party), `mandates` (the Mandates of an Instance, keyed by the Instance) `acceptances` (the Acceptances whose issuer is a Party, keyed by that Party), `selection` (the `subject-selection` Acceptances of a class, keyed `dCBOR(["selection", class])`) `policies` (the RestrictionPolicies of a target, keyed `dCBOR(["policies", target])` with the target as in `policy-content`; `policy_set` adds a policy to its target's entry and moves it when an amend changes the target) and `foreign` (the `foreign-authority` Acceptances of a foreign domain, keyed `dCBOR(["foreign", DomainID])`). The index `dCBOR(["key", kid])`, with `kid` the RFC 7638 thumbprint of an Instance's current key, holds that Instance's id; creating, rekeying and recovering an Instance write it, and rekeying and recovering remove the old key's entry.

<a id="L0-META-6"></a>**L0-META-6. Stored status.** A stored object carries its content, a position `since` and, once it has ended, `ended` with the position and the way it ended. For a Grant, `since` is the position that created it and stays the same when it is amended, so that holdings naming it stay valid; each amend raises its `revision` by one. For every other object, `since` is the position that created or last changed it. Ending is terminal: no meta-action changes an object with `ended` (reason `meta-ended`). Status that depends on time or on other objects, such as expiry or a revoked ancestor, is derived when it is read and never stored.

<a id="L0-META-7"></a>**L0-META-7. Genesis.** The state at position 0 holds the objects that Genesis creates from its `genesis-fields`: the meta-anchor with scope `"domain"` as Anchor 0, then each entry of `anchors`, each Grant of `grants` with its `children` index (a Genesis Grant names its Anchor by position, 0 being the meta-anchor, because the ids derive from the DomainID, which is this record's own digest), and each Acceptance of `acceptances`, with ids by [L0-META-4](#L0-META-4) and `since` 0. A Genesis record with a field that `genesis-fields` does not define is rejected.

## 3. Powers

<a id="L0-META-10"></a>**L0-META-10. Root power.** The actor's Party holds the root of an Anchor when the root is `{sole: P}` with `P` the actor's Party, or `{joint: …}` with the actor's Party among `parties`. A joint root of `k` adds a requirement for `k − 1` contributions of class `co_root`, single use, bound to the intent digest, from distinct Parties. The Anchor's `root_terms` are added as requirements. An Anchor that has ended gives no power.

<a id="L0-META-11"></a>**L0-META-11. Lineage power.** For a Grant `G`, the actor has lineage power when it holds the root of the Anchor at the top of `G`'s lineage, or its Party is the extensional holder of a Grant above `G` in that lineage that has not ended. A lineage longer than 16 is rejected (reason `meta-depth`).

<a id="L0-META-12"></a>**L0-META-12. Own Instance.** A Party has power over its own Instances: those whose `party` is the actor's Party and that have not ended.

<a id="L0-META-13"></a>**L0-META-13. Basis.** The Exercise basis names the power it uses: `{anchor: A}` for root power over `A`, `{holding: …}` for a holding, and `{public: G}` for the self-acting actions `party_register` and `instance_create`. A basis that does not match the meta-action is refused (reason `meta-basis`). Actions decided by lineage power, by power over one's own Instances, or by a Grant like any domain action (`contribute`) are not read against the basis here; the basis is checked by the evaluation of the Exercise. When the basis is `{holding: [G, P, s]}` and the action is not `contribute`, the holding's own terms apply too, whatever power decides the action: every Grant of `G`'s lineage and the lineage's Anchor have not ended, `now` lies within each Grant's validity window, and the first live Mandate of the actor Instance (by id under `mandates`) is not pinned to another holding; otherwise the reason is `holding-terms`. The requirement terms of every Grant of the lineage are added to the meta-action's requirements, and a decision point that finds one of them unmet refuses the Exercise with `holding-terms`, except for a break-glass Grant, whose own terms keep their approval path. Root power, lineage power and power over one's own Instances are decided as before. Vectors: [`core/1/meta-holding-terms.json`](../../conformance/vectors/core/1/meta-holding-terms.json).

## 4. The meta-actions

<a id="L0-META-20"></a>**L0-META-20. Anchors.** `anchor_create` needs root power over the basis Anchor, and the new scope must lie within that Anchor's scope; a scope of `"domain"` is never created. `anchor_transfer`, `anchor_amend` and `anchor_retire` need root power over the Anchor named, which must also be the basis. The meta-anchor is never retired. A root change, by `anchor_transfer` or by an `anchor_amend` with a `root`, adds for each Party the new root names and the old one does not a requirement for one contribution of class `accept_root` from that Party (`source: {party: P}`), single use, bound to the intent digest: no Party becomes a root without its own act on the exact change.

<a id="L0-META-20a"></a>**L0-META-20a. Conditional transfer.** `anchor_transfer` may also have the basis `{holding: [G, P, s]}`: `P` is the actor's Party and the capacity `own` (reason `meta-basis`); `G` has not ended, `P` is its extensional holder with `s` its `since`, `G`'s basis is `{anchor: A}` for the Anchor `A` named, its authority-set names `anchor_transfer` exactly and its constraints carry at least one `claim_held` while-condition (reason `meta-not-authorized`); the evaluation's trusted time lies within `G`'s validity (reason `meta-ended`); and the new root is `{sole: P}` (reason `meta-not-within`). The requirements are `A`'s root terms and `G`'s requirements; no `accept_root` term is added, the holder's own Actor Intent Statement being its consent. The decision point denies the Exercise with `ended/lapsed` when a while-condition of `G` does not hold.

<a id="L0-META-21"></a>**L0-META-21. Dispositions.** `anchor_transfer`, `anchor_retire` and `party_depart` carry a disposition that names exactly the dependent Grants that have not ended, each with `keep` or `revoke`; there is no default (reason `meta-disposition`). `revoke` ends the Grant. `keep` is allowed only on transfer.

<a id="L0-META-22"></a>**L0-META-22. Admission.** `party_register` creates, in one record, the Party's admission and its self-anchor with scope `{party: P}` and the given root. The payload's Party must be the actor's Party, and a Party is registered at most once. The payload names the Party's `actor_kind` (`human`, `agent`, `system`, `machine` or `organization`); a payload without one is malformed. The admission records it and no action changes it. `party_depart` needs root power over the meta-anchor; it retires the self-anchor with its disposition and ends the Party and its live Instances.

<a id="L0-META-23"></a>**L0-META-23. Instances.** `instance_create` is for the actor's own Party, which must be admitted; the new Instance's id is the one [L0-META-4](#L0-META-4) gives and must be the actor Instance, so the new key signs its own creation. An Instance key, here and in `instance_rekey` and `instance_recover`, is an Ed25519 key or a P-256 key ([L0-SIG-4](signatures.md#L0-SIG-4)) that signs with ESP256; any other key makes the payload malformed. An optional Mandate is bound in the same record. `instance_rekey` is done by the Instance itself. `instance_terminate` is done by the Instance's Party or with root power over that Party's self-anchor. `instance_recover` is done by the Party; it ends the old Instance and creates exactly one successor that inherits nothing.

<a id="L0-META-24"></a>**L0-META-24. Mandates.** `mandate_bind`, `mandate_rebind` and `mandate_revoke` are done by the Party of the Mandate's Instance. A pin names a holding of that Party that has not ended, with its `since`.

<a id="L0-META-24a"></a>**L0-META-24a. Mandate origins.** A `mandate-envelope` may carry `origins`, the origins one task may read and write ([L0-EVAL-16a](evaluation.md#L0-EVAL-16a)). A `mandate_rebind` whose read or write set is not a subset of the Mandate's current one is expansion class ([L0-META-28](#L0-META-28)), as is one whose authority set widens.

Vectors: `meta.json`: `mandate-bind-origins`, `mandate-rebind-widen-origins`, `mandate-rebind-narrow-origins`.

<a id="L0-META-25"></a>**L0-META-25. Grant issue.** With basis `{anchor: A}` the actor needs root power over `A` and the Grant's resource must lie within `A`'s scope. With basis `{holding: [G, P, s]}`, `P` must be the actor's Party and the extensional holder of `G`, `s` must be `G`'s `since`, `G` must not have ended, and the new authority must be within `G`'s by the child-within-parent check of [L0-ALG-70](algebra.md#L0-ALG-70) (reason `meta-not-within`). The Grant's `agency` may hold only `own` and `{for: Q}` where `Q` is the issuing Exercise's principal (reason `meta-agency`).

<a id="L0-META-26"></a>**L0-META-26. Grant changes.** `grant_amend` and `grant_revoke` need lineage power over the Grant. An amend keeps the GrantID, raises `revision` by one and, for a Grant with a holding basis, stays within its parent. `grant_renounce` is done by the extensional holder.

<a id="L0-META-27"></a>**L0-META-27. Domain objects.** `acceptance_*`, `policy_*` and `claim_issue` need root power over the meta-anchor. A `policy-content` names the schema `access/restriction/v1`; any other schema is malformed. An Acceptance's `issuer` is a Party, except that an Acceptance whose `use` is `foreign-authority` has as issuer a foreign domain, `{foreign: {domain, binding}}`, with its pinned binding keys (each `kid` the thumbprint of its key), and no other issuer; any other pairing of issuer and use is malformed. Each class of a `foreign-authority` Acceptance is an action namespace of that domain. An amend keeps an Acceptance's `issuer` and `use`. A class has one membership issuer: a `subject-selection` Acceptance is refused when a live one of another issuer names the same class (reason `meta-not-within`). A Claim issued by `claim_issue` has the actor's Party as its issuer and the issuing Exercise's object id as its ClaimID; without a `validity` it is stored with the validity `[0, 2^64 − 1]`. The Claim also gets its membership entry `dCBOR(["member", class, subject, ClaimID])` holding the ClaimID. A `bound_intent` or `supersedes` in the payload is stored with the Claim, and `supersedes: S` also writes `dCBOR(["successor", S, ClaimID])` holding the ClaimID. An amend that drops a class from a `subject-selection` Acceptance removes the Acceptance from that class's `selection` entry, and an entry left empty is removed.

<a id="L0-META-27a"></a>**L0-META-27a. Self-restriction.** The root of a Party's self-anchor `A` (scope `{party: P}`) may also run `policy_set` with basis `{anchor: A}` when the policy's `target` is `{anchor: A}`; its requirements are `A`'s root requirements. Such a `policy_set` must narrow ([L0-META-28](#L0-META-28)): a new policy whose every statement is a `forbid`, or an amend that keeps every old statement and adds only `forbid` statements, without `defaults`; anything else is `meta-not-within`. A `policy_set` with a self-anchor basis and any other target is `meta-basis`, and a non-Party Anchor naming itself as target is `meta-basis` too. Retiring such a policy stays with the meta-anchor root.

<a id="L0-META-30"></a>**L0-META-30. Contributions.** `contribute` is authorized like any domain action: its intent's resource is `access.contribution` with the path `[class]`, and the actor needs a Grant covering it. An anonymous actor never contributes. A contribution of class `accept_root` is also authorized by root power over the actor Party's own self-anchor, named as the basis `{anchor: A}` with `A`'s scope `{party: P}` and `P` the actor's Party, so that a Party asked to become a root can consent without a Grant. The payload's `target` is the digest of the intent the contribution is for. An allowed `contribute` writes a `contribution-state` under the key of its ExerciseID with the actor's Party and Instance.

<a id="L0-META-32"></a>**L0-META-32. Budget release.** The `exercise-state` an allowing decision writes lists, under `draws`, each budget counter it drew from with the amount drawn, `released` 0 and, for an `amount` term, its `unit`. `consumption_release` names an `exercise` and its `grounds`. The actor Instance must be that Exercise's actor, or the actor's Party the extensional holder of a Grant that has not ended and whose budget counter the Exercise drew from (reason `meta-not-authorized`); an Exercise without `exercise-state` is `meta-unknown`. Each ground is a stored Claim that has not ended, bound to the Exercise's intent digest, of class `access_non_execution` or of class `access_actual_amount` with a non-negative integer value; anything else, or two `access_actual_amount` grounds with different values, is `meta-not-within`. With an `access_non_execution` ground each draw's target is its `drawn`; otherwise, with actual amount `a`, a draw with a `unit` targets `drawn − min(a, drawn)` and a count draw 0. Each draw returns `target − released` when positive and its `released` becomes the target. The grounds are added to `grounds`. A ground already in `grounds`, or a release that returns nothing, is `meta-release-exceeds-draw`. The release writes the updated `exercise-state`; a release is expansion class. Each returned amount raises the counter whose key is the draw's key with `"released"` in place of `"budget"`, and a budget's remaining is its capacity minus its used amount plus its released amount.

<a id="L0-META-33"></a>**L0-META-33. Named AuthoritySets.** `authority_set_define` needs root power over the meta-anchor. It writes version `n` of its `name`, where `n` is one more than the version stored under `dCBOR(["authority_set", name])` (1 when there is none): that key then holds `n`, and `dCBOR(["authority_set", name, n])` holds `{authority, since}`. A version never changes. The digest of a version is `SHA-256("access/authority-set/v1" ‖ 0x00 ‖ dCBOR(authority-set))`. A `grant_issue` whose content has `named: {name, version, digest}` is refused with `meta-unknown` when that version does not exist, and with `meta-not-within` when the digest differs or the Grant's authority-set is not within the version's. A `grant_amend` may carry a new `named` pin; the amended authority-set must lie within the pinned version, the new one or the one already pinned. Defining a version changes no Grant.

<a id="L0-META-34"></a>**L0-META-34. Schema definitions.** An Acceptance whose `use` is `schema-definition` carries `spp`, a Schema Publication Package, and no other use carries one; its `issuer` is `spp.publisher` (else `meta-malformed`). An SPP lists Action Schemas with distinct `(name, major)`. `acceptance_establish` adds such an Acceptance to the set under `dCBOR(["schemas", spp.namespace])`. An amend keeps `spp.namespace` (`meta-not-within`) and is expansion class. The digest of an Action Schema is `SHA-256("access/action-schema/v1" ‖ 0x00 ‖ dCBOR(action-schema))` and is the `schema` of its action reference. An Action Schema may declare `reversibility` (`reversible`, `compensable` or `irreversible`), independent of its Consequence Tier; a decision or an approval policy reads an absent one as `irreversible`, and a render carries the declared one so a surface offers "Undo" only for a reversible action (E47).

<a id="L0-META-28"></a>**L0-META-28. Expansion.** Each allowed meta-action is either expansion class or not. Creating anything except a RestrictionPolicy (which only narrows), changing an existing RestrictionPolicy, widening a Grant or a Mandate, changing a root, lowering root terms, retiring a policy and every Acceptance change except revoke are expansion. Revoke, renounce, terminate, rekeying an Instance, `projection_issue` and narrowing amends are not; ending an object records `ended` and leaves `since` as it was. An Acceptance amend narrows when its classes are a subset, its subject is within the old one, its assurance floor is at least the old one in every dimension, its validity lies within the old one, `ingest_until` and `issued_until` are added or earlier, and its quota is not removed or raised.

<a id="L0-META-29"></a>**L0-META-29. Effects.** An allowed meta-action writes its state changes as the `effects` of its decision record ([L2-REC-2](../l2/README.md#L2-REC-2)), and the `children`, `instances`, `mandates`, `acceptances` and `selection` indexes with them. Effects are sorted by the bytes of their keys, a key appearing once; its requirements are a set sorted by the bytes of each term's canonical encoding. A RestrictionPolicy's `version` is not stored: it is `SHA-256("access/policy/v1" ‖ 0x00 ‖ dCBOR(policy-content))`, computed when the policy is read.

<a id="L0-META-31"></a>**L0-META-31. Reasons.** A refused meta-action names one reason: `meta-malformed` (the payload does not decode), `meta-action` (not a core action), `meta-unknown` (an object it names does not exist), `meta-ended` (an object it changes, or the Anchor or holding it relies on, has ended; also a second `party_register` of a Party), `meta-not-authorized` (the actor lacks the power; also a pin naming a holding of another Party or another `since`), `meta-not-within` (a scope, authority or Acceptance change outside what it must stay within, including an amend that changes an Acceptance's `issuer` or `use`), `meta-agency`, `meta-disposition`, `meta-basis` (also retiring the meta-anchor), `meta-depth` or `meta-release-exceeds-draw` (a release that reuses a ground or returns nothing; its blocker is `budget-exhausted` with subcode `release-exceeds-draw`).

<a id="L0-META-35"></a>**L0-META-35. Projection issue.** `projection_issue` issues a projection to the actor Instance, which is always its holder. Its `bounds` is a `canonical-authority` whose validity ends at the horizon and whose requirements are the ones a verifier checks locally; `audience` names the verifiers and `profile` the connectivity profile, whose variant must belong to its class (else `meta-malformed`). With basis `{holding: [G, P, s]}`, `P` must be the actor's Party (reason `meta-basis`), the extensional holder of `G` with `s` its `since` (reason `meta-not-authorized`), and `G` must not have ended. With basis `{anchor: A}` the actor needs root power over `A` and its requirements are added; a `{public: G}` basis is `meta-basis`. A projection is not a delegation and the depth rule of [L0-ALG-73](algebra.md#L0-ALG-73) does not apply. Each of these must hold, else the reason is `meta-not-within`: with a holding basis, every Grant of `G`'s lineage and its Anchor have not ended, the declared capacity is in `G`'s `agency`, the bounds' authority-set is `⊑` `G`'s ([L0-ALG-50](algebra.md#L0-ALG-50)), its validity lies within `G`'s, its while-conditions include `G`'s and its requirements are at least as strict as `G`'s ([L0-ALG-61](algebra.md#L0-ALG-61)); with an Anchor basis, the bounds' resource lies within `A`'s scope and the capacity is `own`; the bounds carry no delegation depth and no `downstream_holder_class`; when the actor Instance has a live Mandate (the first by id under `mandates`), the bounds' authority-set is `⊑` its envelope's, its validity lies within the envelope's and its requirements are at least as strict; and the horizon `h` satisfies `now ≤ h` and `h − now` is at most the CT1 validity ceiling of 24 hours, `now` being the evaluation's trusted time. An allowed `projection_issue` writes `projection-state` under `dCBOR(["projection", ExerciseID])`: the holder Instance, the Exercise basis, the digest of the bounds `SHA-256("access/bounds/v1" ‖ 0x00 ‖ dCBOR(canonical-authority))`, the horizon and the audience. It is not expansion class and its tier is CT1. An optional `offline_slice` (`{? count: uint, ? amounts: {unit => uint}}`, at least one non-zero; else `meta-malformed`) is allowed only with a holding basis and a profile class of `offline` or `intermittent` (else `meta-not-within`); the decision point draws it from every budget term of the lineage whose dimension it names, at commit, and the Kernel checks those budgets as it checks an intent's ([L0-EVAL-15](evaluation.md#L0-EVAL-15)).

Vectors: [`core/1/meta.json`](../../conformance/vectors/core/1/meta.json), operation `meta.apply`. Each case gives the state, the DomainID, the ExerciseID, the position `pos`, the trusted time `now`, the actor's Party and Instance, the basis, the capacity and the payload.

<a id="L0-META-36"></a>**L0-META-36. Handover and recovery.** `domain_handover` and `domain_recover` are domain-scope: the basis is `{anchor: M}` with `M` the meta-anchor and the capacity `own` (else `meta-basis`), and the actor needs root power over `M` (`meta-not-authorized`). The provider binding is the value under `dCBOR(["provider_binding"])`; a Genesis `binding` writes it first, and only these two meta-actions change it, so no Anchor change can (PI-15). Each writes `{binding, cited, how, since}` and, for every old key not in the new binding, `dCBOR(["superseded", kid])` holding `{cited, pos}`; a new key that is already superseded is `meta-not-within`. `domain_handover` needs `M`'s root requirements and is expansion class (CT3). `domain_recover` needs the recovery entry under `dCBOR(["recovery_entry"])` (`meta-not-authorized` without one), written by Genesis from `meta_anchor.recovery`; a Genesis whose entry names a holder outside `M`'s root or a key of the Genesis binding is `meta-not-within` (SEC20). Its requirement is one `recover` contribution term of the entry's threshold from distinct Instances, bound to the intent, with `hardware_bound`, `human_presence`, `phishing_resistant` and `uv` at 1, in place of `M`'s root requirements and with no CT3 quorum. `cited_checkpoint.size` must equal `n` and `witness_claims` must be non-empty (`meta-not-within`); each named Claim is read from the state and counts as a witness head when it is a live `checkpoint` Claim within its validity and the state holds its head `checkpoint-ref` under `dCBOR(["witness_head", ClaimID])` (written by the checkpoint ingest), its time the Claim's `issued_at`. The rollback guard (`recovery.guard`) then runs with `replica_head.size` as R* and `fork` declared when non-empty: `rollback-guard` refuses the recovery with that reason, any other guard failure is `meta-not-within`. On arm (ii) `M`'s root requirements are added, and the declared `lost_suffix` must be `{from: N, to: highest}` exactly when that range is not empty, and absent otherwise (`meta-not-within`). An allowed recovery also writes `dCBOR(["recovered"])` holding `{at, pos, n}`, `at` the evaluation's trusted time; an Actor Intent Statement issued before `at` whose nonce the continuing lineage does not hold is closed (`recovery.pre_recovery`, blocker `nonce-closed/pre-recovery`).

<a id="L0-META-37"></a>**L0-META-37. Version activation.** `version_activate` needs root power over the meta-anchor. The value under `dCBOR(["versions"])` is `{floor, activated, at}`; the minimum in force at time `t` is `floor` raised track by track to `activated` once `t ≥ at + 90 days` (`version.transition`). An activation writes `{floor: the minimum in force now, activated: versions, at: now}`, with no value read as all-zero versions. It is expansion class when `versions` lowers any track of the previous `activated` (`version.downgrade`): a lower core or meta-schema version, a lower or dropped profile floor, or a dropped pinned schema; then it is CT3 with at least a 24-hour time-lock. Otherwise it narrows (CT1).

<a id="L0-META-38"></a>**L0-META-38. Algorithm retirement.** `algorithm_retire` needs root power over the meta-anchor and adds its algorithm to the set under `dCBOR(["retired_algorithms"])`. It always narrows (CT1); a provider, holding no root power, cannot declare an algorithm broken (§15.16).
