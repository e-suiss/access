# Service dependencies

Generated by `cargo xtask seam-dependencies` from the code and `declared.toml`; `cargo xtask check no-privileged-path` fails when it is stale.

Every auxiliary service and product twin is built the way a third party would build it: on the published crates only, over Access's public endpoints. What each one still depends on is listed here.

## `access-executor` (services/executor)

Crates:

- `esuiss-access-kernel`
- `esuiss-access-sdk`
- `esuiss-crypto`

Access endpoints:

- `/.well-known/access-domain-metadata/{}` (public)
- `/access/v1/claims:ingest` (public)
- `/access/v1/evaluation` (public)
- `/realms/{}/v1/vault/releases` (not in a public contract)

Declared:

- Client certificate: the transport authenticates it as its own PEP (L1-ADP-2); the token vault's Resource lists that PEP by thumbprint
- Operator Party: it is an Instance of its operator's Party, registered by its own self-signed Exercises (AG-40, L0-META-7)
- Custodial key: none: upstream tokens live in its memory for one Exercise and its Instance key is its own

## `access-hr-connector` (services/hr-connector)

Crates:

- `esuiss-access-kernel`
- `esuiss-access-sdk`
- `esuiss-crypto`

Access endpoints:

- `/admin/v1/realms/{}/hr-sources/{}/records:batch` (public)
- `/admin/v1/realms/{}/intents` (public)

Declared:

- Operator Instance: its writes are idp.hr.import Exercises signed by an Instance key of the operator who registered the connector; the draft carries the operator's DPoP-bound read token (TN-110, OP-151 m.3 (c))
- Domain Acceptances: the HR source's Claims select holders only through the domain's own CT3 subject-selection Acceptance of its issuer (TN-95, INV-16)
- Custodial key: none: the HR system's credential and the Instance key are files the operator provides; it keeps no record content

## `access-product-twin` (services/product-twin)

Crates:

- `esuiss-access-kernel`
- `esuiss-access-sdk`
- `esuiss-crypto`

Access endpoints:

- `/.well-known/access-domain-metadata/{}` (public)
- `/access/v1/claims:ingest` (public)
- `/access/v1/evaluation` (public)
- `/access/v1/publications` (public)
- `/access/v1/publications:status` (public)
- `/access/v1/tenants/{}/pairing` (public)
- `/access/v1/tenants/{}/pairing/challenges` (public)

Declared:

- Platform client: the platform realm's root registers its client with `idp.client.register` (OP-149 m.4); a third-party product is registered the same way
- Client certificate: the transport authenticates it as its own PEP (L1-ADP-2) with a certificate from any CA the deployment trusts
- Domain Acceptances: its schema and Claims take effect only through the domain's own Acceptance Exercises (§7.9.10.3, PI-3)
- Custodial key: none: its service and client keys are its own
